# 广州中考志愿模拟填报录取 - 微信小程序开发规范

## 项目概述

本项目是已上线的微信小程序，帮助广州中考考生和家长理解投档规则、模拟志愿填报、分析录取概率。基于广州市中考实际录取数据（2023-2026年），严格遵循广州市招生考试委员会办公室（https://gzzk.gz.gov.cn）发布的官方政策。

**菜单结构：**

一级菜单（TabBar）指向导航页面：
1. **首页** - 展示所有功能导航入口和官方链接
2. **规则总览** - 导航页面，提供梯度投档流程、志愿案例分析入口
3. **模拟填报录取** - 导航页面，提供2025第二批、2025第三批模拟填报入口
4. **历史数据分析** - 导航页面，提供历年录取数据、分数段统计入口

二级菜单（在各导航页面中清晰展示）：
- **规则总览**：
  - 梯度投档流程
  - 志愿案例分析
- **模拟填报录取**：
  - 2025第二批模拟填报（名额分配）
  - 2025第三批模拟填报
  - 第二批2026年预测
  - 第三批2026年预测
- **历史数据分析**：
  - 各学校历年录取数据
  - 历年各分数段统计和排名
  - 学校历史录取分数变化

**设计特点：**
- 使用CSS绘制的专业图标，替代emoji
- 清晰的卡片式布局，用户无需学习即可理解
- 每个功能项有明确的标题、描述和操作提示
- 统一的视觉风格和交互反馈

**核心功能模块：**
1. **录取规则展示** - 梯度投档、志愿优先、分数优先等规则的流程图解
2. **2025第三批模拟填报** - 示范性/省一级高中，6个志愿（2025年数据 + 2026年预测）
3. **2025第二批模拟填报** - 名额分配招生，3个志愿（校内竞争模式）
4. **历史数据查询** - 2023-2025年各校录取分数线、分数段统计、排名估算
5. **2026年预测** - 根据适应性测试成绩估算中考分数并模拟填报
6. **录取案例分析** - 第三批案例（10个）+ 名额分配案例（5个）

## 编码规范

### JavaScript 编码风格

1. **文件结构**：每个页面4个文件（.js / .wxml / .wxss / .json），命名与目录一致
2. **模块引用**：使用 CommonJS `require()`，不用 ES Module
   ```javascript
   const app = getApp()
   const admission = require('../../utils/admission.js')
   ```
3. **Page 结构**：
   ```javascript
   Page({
     data: { /* 页面数据 */ },
     onLoad() { /* 页面加载 */ },
     // 事件处理函数使用 on 前缀
     onScoreInput(e) { },
     onNavigate(e) { },
     // 业务方法直接命名
     loadSchoolList() { },
     calculate() { },
     reset() { }
   })
   ```
4. **事件处理**：通过 `e.currentTarget.dataset` 获取 dataset，通过 `e.detail.value` 获取表单值
5. **数据更新**：使用 `this.setData()` 更新视图，避免频繁调用
6. **页面导航**：Tab页使用 `wx.switchTab`，子页面使用 `wx.navigateTo`
7. **提示反馈**：使用 `wx.showToast` / `wx.showModal`，统一用中文提示

### WXML 模板规范

1. **列表渲染**：统一使用 `wx:for` + `wx:key="id"` 或 `wx:key="order"`
2. **条件渲染**：使用 `wx:if` / `wx:elif` / `wx:else`
3. **事件绑定**：使用 `bindtap="methodName"`，传参用 `data-xxx`
4. **页面容器**：顶层统一使用 `<view class="container">`
5. **不用自定义组件**：项目当前未使用 components 目录，保持简单直接

### WXSS 样式规范

**严格遵循已有设计系统**，详见下方"设计系统"章节。关键原则：
- 使用 `rpx` 单位（不用 px）
- 圆角统一 `12rpx`（卡片）或 `8rpx`（按钮/标签）
- 阴影统一 `box-shadow: 0 2rpx 12rpx rgba(0, 0, 0, 0.08)`
- 不引入第三方 UI 框架

### 数据规范

1. **学校数据结构**（见 `references/school-data-schema.md`）
2. **年份处理**：每年6-7月广州招考网公布新数据后更新 `data/` 目录
3. **梯度控制线**：每年公布后同步更新 `app.js` 的 `globalData.gradientLines` 和 `utils/admission.js` 的 `GRADIENT_LINES`（两处需保持一致）

## 广州中考政策规则

政策权威来源：广州市招生考试委员会办公室官网 https://gzzk.gz.gov.cn/zkzz/zkxx/wjtz/

### 录取批次体系

广州中考分为**四个批次**，按顺序依次投档录取。考生一旦被任一批次录取，不再参加后续批次：

| 批次 | 包含内容 | 志愿数 | 说明 |
|------|----------|--------|------|
| **第一批次** | ①普通高中特长生 ②自主招生 ③外语/艺术类普高 ④公办普高港澳子弟班 ⑤中本贯通（3+4） ⑥中职三二分段及省级以上重点特色专业 | 各类1个；港澳子弟2个；中本贯通2个；中职4个 | 特色项目及中职提前批 |
| **第二批次** | 名额分配招生（公办示范性普高和省一级普高） | **3个** | 50%招生计划分配到初中，校内竞争，仅限户籍生 |
| **第三批次** | 示范性普高剩余招生计划、引入优质资源新建普高部分计划 | **6个** | 本系统核心批次，全市竞争，梯度投档 |
| **第四批次** | 普通高中其他（剩余）计划、综合高中、中职学校其他（剩余）计划 | 普高6个 / 中职6个 | 非示范性普高及中职 |

> **补录**：统一安排在第四批次中职学校其他计划录取之前进行。未完成招生计划的普高/综合高中/中本贯通/重点中职可参加补录。被上述类型录取但逾期未注册的考生，注销结果后只能参加中职学校剩余计划的补录。
>
> 权威来源：《广州市招生考试委员会办公室关于做好2025年高中阶段学校招生填报志愿工作的通知》

### 梯度投档规则（核心算法）

**梯度控制线划分**：以一定分差划定多个梯度，高分梯度优先投档。

2025年梯度线：
- 第一梯度：≥707分
- 第二梯度：≥667分
- 第三梯度：≥627分
- 第四梯度：≥587分
- 第五梯度：≥547分
- 第六梯度：≥507分
- 普高最低线：≥487分

**投档优先级**（从高到低）：
1. **梯度优先**：高分梯度考生优先投档
2. **志愿优先**：同一梯度内，按志愿顺序投档
3. **分数优先**：同一志愿内，高分考生优先
4. **同分序号**：分数完全相同时，按同分序号排序

**录取判定逻辑**（第三批核心算法，详见 `references/admission-algorithm.md`）：
- **资格检查**：分数有效性 → 梯度等级判定 → 普高线门槛 → 志愿有效性
- **三大投档分支**：
  - **分支A（跨梯度）**：学校梯度低于考生梯度，比较考生分数与学校最低分
  - **分支B（同梯度·已满）**：先末位志愿截断（lastVolunteer < 当前志愿则直接跳过），再比较
  - **分支C（同梯度·未满）**：学校有剩余计划，直接比较
- **比较基准选择**：当前志愿恰为末位志愿时用 `(lastScore, lastScoreSeq)`；否则用 `(schoolMinScore, schoolMinScoreSeq)`

### 名额分配规则（第二批，详见 `references/gradient-rules.md`）

公办示范性普高和省一级普高，将不低于50%招生计划分配到各初中。

- **招生学校范围**：公办示范性普高（国家级/市级）和省一级普高
- **分配方向**：省/市属高中面向全市；区属高中仅面向本区（老三区越秀/海珠/荔湾按三个独立区域）
- **报考资格**（须同时满足）：①广州市户籍（或政策性照顾资格）②应届毕业生 ③同一初中就读满三年
- **仅限户籍生**：普通非户籍生（随迁子女）不能参加名额分配
- **竞争方式**：校内竞争（同校符合条件的考生竞争分配到该校的名额），各初中实际录取分数可能不同
- **录取控制线**：= 该校近三年统招首批次户籍生录取最低分的平均值下降40分（去尾取整），不低于普高最低控制线
- **投档方式**：梯度控制线上志愿优先，1:1比例，先高梯度再低梯度，梯度内志愿优先
- **志愿数**：3个
- **不享受加分**：只看原始投档分（裸分）
- **参考科目**：示范性高中C级及以上，非示范性D级及以上
- **未完成计划**：并入第三/四批次，不降分录取

### 考生分类

| 类型 | 说明 | 录取差异 |
|------|------|----------|
| 户籍生 | 广州市户籍 | 录取分数一般较低 |
| 非户籍生 | 非广州市户籍 | 部分学校录取分数更高或有额外限制 |

### 同分序号规则

同分考生按以下优先级逐级比较：
1. **语数英三科总分**：语文+数学+英语三科成绩之和高者优先
2. **数学单科**：数学分数高者优先
3. **语文单科**：语文分数高者优先
4. **英语单科**：英语分数高者优先
5. **道法+历史总分**：道德与法治+历史两科成绩之和高者优先
6. **物理+化学总分**：物理+化学两科成绩之和高者优先

## 开发工作流

### 新增页面流程

1. 在 `pages/` 下创建4个文件：`xxx.js` / `xxx.wxml` / `xxx.wxss` / `xxx.json`
2. 在 `app.json` 的 `pages` 数组中注册路径
3. 如需加入 TabBar，更新 `app.json` 的 `tabBar.list`
4. 如是子页面，在对应菜单入口页的 `menuItems` 中添加条目
5. 严格遵循已有设计系统和编码规范

### 数据更新流程

1. 从广州招考网获取新年度录取数据
2. 更新 `data/schools.js`（主数据源）和新年度文件如 `data/schools2026.js`
3. 更新 `app.js` 的 `gradientLines`
4. 更新 `utils/admission.js` 的 `GRADIENT_LINES` 和 `GRADIENT_INFO`
5. 更新分数段统计数据 `data/scoreDistribution.js`
6. 更新页面文案中的年份引用

### 算法修改注意事项

- `utils/admission.js` 是核心文件，修改前务必理解完整投档流程
- 使用 `test-cases.js` 验证算法正确性
- 梯度控制线在 `app.js` 和 `admission.js` 两处需保持同步
- 第三批和第二批使用不同的录取算法

## 已知注意事项

1. **梯度线不一致**：`app.js` 的 globalData（707/662/622/582/542/502）与 `admission.js`（707/667/627/587/547/487）的梯度线数值不同，需确认哪个是最新年度数据并统一
2. **TabBar 无图标**：当前 TabBar 未配置图标，仅使用文字
3. **无自定义组件**：项目未使用 `components/` 目录，页面逻辑直接内联
4. **无后端**：纯前端小程序，所有数据和计算在本地完成
5. **数据文件较大**：`historicalSchools.js` 约364KB，注意小程序包体积限制
